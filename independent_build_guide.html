Part 2: Build Your Own AI App from Scratch 🚀

Welcome to Part 2 of the AI Workflows Working Session!

In Part 1, you built an AI Meeting Assistant. Under the hood, it followed a simple pattern that powers a huge number of real AI tools:

Messy text in  →  Instructions + Schema  →  Gemini API  →  Structured JSON  →  Clean UI out

In Part 2, you'll use that same pattern to build a completely new app for a business task you care about. You won't write it line by line. Instead, you'll direct Gemini to write it with you, one step at a time, using the prompts in this guide.

You have 50 minutes. Each step has a suggested time box so you finish with something that works.

⚠️ Before You Start: Three Rules

  1. Never paste your API key into the Gemini chat. Gemini will write code with a placeholder like YOUR_API_KEY. You paste the real key into your file yourself.
  2. Use sample or made-up data only. No real client info, employee data, or anything confidential.
  3. Save a backup first. Duplicate your Part 1 file as meeting_assistant_backup.html. Create a new file called index.html for your new app.

🧱 The Anatomy of Your App

Every app you build today has the same six parts. Each step below builds one of them.

# Part What it does In Part 1 it was…
1App ideaDefines the user, input, and outputMeeting notes → action items
2JSON schemaThe exact shape of the AI's answersummary, keyDiscussions, actionItems
3System instructionThe AI's role and rules"You are an expert executive meeting assistant…"
4UI shellThe page: input box, button, results areaEmerald/teal Tailwind layout
5API callSends text + instruction + schema to Geminifetch() with payload
6RendererTurns the JSON into readable cardsrenderResults(data)

Build in this order. Deciding the output (Steps 1–3) before writing any code is what keeps the app predictable.

Step 0: Prime Gemini with Context (2 min)

Open a new Gemini chat just for this build. Send this prompt first so every later answer stays consistent.

💬 Prompt 0: Set the context

I'm building a single-file web app (one index.html) during a workshop. Please act as my
coding partner for the next 45 minutes. Constraints for everything you write:
- One HTML file only. Tailwind CSS via CDN, Font Awesome via CDN, plain JavaScript.
- It calls the Gemini API directly from the browser using fetch() and the
  generateContent endpoint.
- It uses a systemInstruction and a responseSchema with
  responseMimeType "application/json" so the output is always structured JSON.
- Use the placeholder YOUR_API_KEY. Never ask me for my real key.
- Keep code beginner-friendly with short comments.
Wait for my next message before writing any code. Reply "Ready" if you understand.

💡 Strong shortcut: Paste your working Part 1 code into this chat with: "This is my working app from Part 1. Use it as the structural template for everything we build next." Gemini will reuse your exact API setup, which avoids most bugs.

Step 2: Design the JSON Schema (5 min)

The schema is the contract between Gemini and your UI. Decide it now and everything else gets easier.

💬 Prompt 2: Design the schema

My app is called [APP NAME]. The user pastes in [INPUT]. I want the AI to return:
[OUTPUT 1], [OUTPUT 2], [OUTPUT 3], [OUTPUT 4].
Write a Gemini API responseSchema for this using uppercase types (OBJECT, STRING,
ARRAY, NUMBER, BOOLEAN). Use clear camelCase field names. Mark all fields as required.
Then show me one short example of JSON that matches the schema.

🟢 Guided: Replace the brackets with: Job Posting Decoder / a job posting / a plain-English role summary / a list of must-have skills / a list of nice-to-have skills / 5 likely interview questions, each with a tip on how to answer.

✅ Checkpoint: Read the example JSON. Would this be useful to your user? If not, ask Gemini to change it now, not later.

Step 3: Write the System Instruction (5 min)

This is the AI's "brain." A good instruction sets a role, a task, and rules.

💬 Prompt 3: Write the system instruction

Write a systemInstruction for my app. The AI should act as [EXPERT ROLE].
Its task is to analyze [INPUT] and fill in every field of the schema above.
Rules to include:
- Use only information in the provided text. Do not invent details.
- If something is missing, say "Not stated" rather than guessing.
- Be concise and practical.
- [ANY RULE SPECIFIC TO YOUR APP]
Keep it under 100 words. Return it as a single JavaScript string.

🟢 Guided: Role = a senior recruiter who helps students prepare for applications. Extra rule = "Interview questions must relate directly to the skills in the posting."

Step 5: Wire Up the Gemini API Call (10 min)

💬 Prompt 5: Connect the API

Replace the TODO with a working async function that:
1. Reads the textarea and stops with a friendly message if it's empty
2. Builds a payload with: contents (the user's text), systemInstruction,
   and generationConfig with responseMimeType "application/json" and our responseSchema
3. Sends it with fetch() to the Gemini generateContent endpoint using YOUR_API_KEY
4. Parses the JSON text from the response
5. Calls renderResults(data)
6. Shows the loading spinner while waiting and a clear error message if anything fails
Use the same model name as my Part 1 app.
Only show me the updated <script> section.

Now paste your real API key into the file where it says YOUR_API_KEY. Do this in your code editor, not in the chat.

Step 6: Render the Results (5 min)

💬 Prompt 6: Display the output

Write the renderResults(data) function. For each field in my schema:
- Show strings as a paragraph in a card
- Show arrays of strings as a bulleted list
- Show arrays of objects as [TABLE / NUMBERED LIST / SEPARATE CARDS]
Give each card a heading and a Font Awesome icon that matches its content.
Match the Tailwind theme we chose. Handle empty arrays gracefully.

✅ Checkpoint: Paste in real-looking sample text and click your button. You should see structured cards appear. 🎉 You now have a working app.

💡 Prompting Pro-Tips

  1. One step per prompt. Asking for the whole app at once produces code that's harder to debug.
  2. Ask for only what changed. End prompts with "Only show me the updated section" to avoid re-pasting the whole file.
  3. Make Gemini explain. Add "Explain what this does in two sentences" when you want to actually learn it.
  4. Correct, don't restart. If output is off, reply with what's wrong ("The cards are too cramped; add more spacing") instead of opening a new chat.
  5. Save versions. Before any big change, duplicate your file (index_v1.html, index_v2.html) so you can always go back.
